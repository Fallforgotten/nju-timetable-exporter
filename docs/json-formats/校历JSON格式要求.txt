校历 JSON 格式要求
格式版本：cengke-calendar-v1
适用实现：蹭课网独立本地版 v0.29.3

一、用途及文件要求
这里的校历是“教学周起点＋每天节次作息”，用于把课表的第几周、第几节换算成具体日期和时间。
不是完整的节假日/调休日历，也不是课表或用户备份。
UTF-8 标准 JSON，不允许注释、尾随逗号。文件最大64 × 1024字节。
网页使用顺序：先选择有效的课表 JSON，再导入对应学期校历。

二、顶层字段
format【必填】：字符串，固定值 "cengke-calendar-v1"。
school【必填】：非空字符串，最多100个长度单位。当前必须是 "南京大学"（比较时去首尾空格）。文件字段本身可表达学校，但当前实现不支持用其他学校校历驱动南大适配器。
term【必填】：非空字符串，最多100个长度单位，须与所选课表学期匹配。
firstMonday【必填】：字符串，格式 YYYY-MM-DD，必须是真实日期且为周一；含义是第一教学周的周一，而非任意开学日期。
periods【必填】：包含1–20项的数组。按实际节次顺序，从第1节开始填写。
note【可选】：建议使用字符串，记录官方来源、校区或注意事项；目前不参与计算和校验，不作为页面展示保证。

三、periods 每项字段
start【必填】：字符串，HH:MM，例如 "08:00"。
end【必填】：字符串，HH:MM，例如 "08:50"。

限制：
- 小时00–23，分钟00–59；不支持 "8:00"、"24:00"、秒数或跨午夜的一节课。
- 每节结束时间必须晚于开始时间。
- 相邻节次不能重叠，后项开始时间必须大于或等于前项结束时间；中间允许午休、课间。
- 数组第1项表示第1节，第2项表示第2节，以此类推；不要删除中间一节或自行插入午休占位项。
- 课表用到第11节时，应至少提供前11节；若缺少所用节次作息，该课程会进入解析待核查。
- 同一份校历只有一套作息，不支持在数组中混合校区或按星期分别设置作息。校区作息不同，请分批处理并核对。

四、学期比较规则
校历和课表比较时会去掉空白、统一长横线，并兼容“第一学期/第1学期”和“2026-2027-1”这种简写。
推荐统一填写 "2026-2027学年 第1学期"，避免多个写法混用。
注意：课表内部行级term的检查更严格，只忽略空格，详见课程表格式文件。

五、示例（仅演示前两节）
{
  "format": "cengke-calendar-v1",
  "school": "南京大学",
  "term": "2026-2027学年 第1学期",
  "firstMonday": "2026-08-24",
  "periods": [
    { "start": "08:00", "end": "08:50" },
    { "start": "09:00", "end": "09:50" }
  ],
  "note": "使用前核对官方校历和所在校区作息"
}

六、换算方式与边界
课程日期 = firstMonday + (周次 - 1) × 7天 + (星期序号 - 1)天；星期一为1，星期日为7。
开始时间取起始节次的start，结束时间取结束节次的end。连续多节中间的课间会包含在这个时间区间内。
单双周依据课表中的教学周序号判断，不依据自然年份的周编号。
目前不处理假期停课、补课、调休、考试或临时地点变化；需要自行确认。

七、错误处理与生效时机
未知format、学校不符、学期不匹配、日期不存在或不是周一、空作息或超过20节、时间错误/重叠均拒绝导入。
校历导入失败时不覆盖已有日期和作息，也不替换已保存的课表。
成功导入只填入表单；重新预览并确认课表导入后才替换当前课表及相关保存数据。
已填入的日期和作息仍可手动调整，调整后须重新预览。
长度按JavaScript String.length计算。

同目录“校历模板.json”含11节作息，沿用项目现有南大2026–2027第一学期公开配置；这是填写示例，不代表自动获取最新校历。实际使用前请核对官方信息。
